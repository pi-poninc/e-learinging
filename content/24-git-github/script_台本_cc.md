# はじめてのGitとコマンド 第5回 GitHubと共有 — ナレーション台本

行数（6行）= スライド枚数（6枚）に一致させること。

| # | スライド | ナレーション |
|---|---|---|
| 1 | タイトル | はじめてのGitとコマンド、第5回です。今回は、GitHub、ギットハブです。前回のGitで保存した履歴を、クラウドに置いて、みんなで使う。その仕組みを学びます。 |
| 2 | GitHubとは | まず、GitHubとは何か。ギットハブは、Gitの保存庫を、インターネット上に置ける、サービスです。クラウドに置くと、いいことが二つあります。一つ、手元のパソコンが壊れても、クラウドに残るので、バックアップになります。二つ、URLで共有すれば、チームの全員が、同じプロジェクトを使えます。ここで注意。Gitは道具、GitHubは置き場所です。名前が似ているので、混同しないようにしましょう。 |
| 3 | 2つの場所 | ここで、二つの場所を押さえます。一つは、ローカル。自分のパソコンの中のことです。ここで編集して、アド、コミットをします。もう一つは、リモート。GitHub上、つまりクラウドのことです。みんなが見られる、共有の置き場所です。やることはシンプルで、手元で作って、クラウドへ送る。そして、クラウドから受け取る。この行き来です。 |
| 4 | push | まず、手元からクラウドへ、送る方です。ギット、プッシュ。手元でコミットしたあと、ギット、プッシュと打つと、GitHubに送られます。アップロード、ですね。これで、クラウド側にも、同じ履歴が反映されます。すると、他の人が、それを見たり、受け取ったりできるようになります。 |
| 5 | pull clone | 次に、クラウドから手元へ、受け取る方です。ギット、プルと打つと、クラウドの最新の変更を、手元に取り込めます。ダウンロード、ですね。そして、ギット、クローン、URLは、まだ手元に無いプロジェクトを、丸ごとコピーしてくるコマンドです。作業を始める前には、まずプルで、最新の状態にそろえる。これが基本のマナーです。 |
| 6 | まとめ | 第5回のまとめです。GitHubは、Gitの保存庫を置く、クラウド。バックアップにも、共有にもなります。ローカル、手元と、リモート、クラウドを、プッシュとプルで行き来します。一人で使っても、バックアップとして便利ですし、複数人なら、共同作業の土台になります。次回は最終回。困ったときの対処と、安全に使うコツ、そして今日から使える最小の手順をまとめます。 |
