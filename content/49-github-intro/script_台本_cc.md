# GitHub入門ダイジェスト — 台本

行数（9行）= スライド枚数（9枚）。

| # | スライド | ナレーション |
|---|---|---|
| 1 | タイトル | GitHub、入門ダイジェスト。黒い画面、つまりコマンドを使わずに、ブラウザとデスクトップアプリだけで、保存・共有・共同作業ができるようになります。全体像を、ざっと掴みましょう。 |
| 2 | なに？ | GitHubがうれしい理由は、3つです。変更の履歴が残って、いつでも前に戻せる。同じファイルを、複数人で安全に扱える。そして、公開して、自分の作ったものを見せられる。 |
| 3 | 言葉4つ | まず、言葉を4つだけ覚えます。リポジトリは、プロジェクトの保管箱。コミットは、変更の記録と、一言メッセージ。プッシュは、クラウドへの反映。クローンは、自分のパソコンに取り込むこと。これだけで大丈夫です。 |
| 4 | はじめ方 | 始め方です。github.comで、サインアップ。そして、二段階認証を、必ずオンにしてください。乗っ取り防止の基本です。見せたくないものは、プライベート、非公開にしておけば安心です。 |
| 5 | リポジトリ | 保管箱、リポジトリを作ります。ニュー・リポジトリから、リードミーを付けて作成。リードミーは、マークダウンで書く、プロジェクトの説明書です。画面上のタブ、コード、イシュー、プルリクエストも覚えておきましょう。 |
| 6 | ブラウザだけ | 実は、ブラウザだけでも作業できます。アド・ファイルでファイルを作り、編集して、コミット・チェンジズ。これが、保存して記録する、という操作です。履歴から、前の状態にも戻せます。 |
| 7 | Desktop | パソコンと同期したいときは、GitHubデスクトップ。クローンでパソコンに取り込み、編集したら、コミット、そしてプッシュ・オリジンでクラウドへ。作業を始める前に、プルで最新を取り込むのがコツです。黒い画面は、一切使いません。 |
| 8 | 共同作業 | 共同作業の道具です。イシューは、やることやバグを貼る付箋。ブランチは、メインを壊さずに試すための、作業用のコピー。そして、プルリクエストは、その変更をメインに入れてくださいという提案で、レビューしてマージします。 |
| 9 | はじめよう | 最後に。パスワードやキーなどの秘密情報は、絶対に上げない。見せたくないものはプライベート。そして、コミットは小さく、こまめに。難しく考えず、まずは今日、リポジトリを1つ作ってみましょう。 |
