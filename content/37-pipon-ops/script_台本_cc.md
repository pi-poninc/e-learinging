| 2 | ねらい | この講座のねらいは、スラック、バックログ、ギットハブといったツールを、piponの案件で実際にどう回すかを覚えることです。正しい手順を暗記するより、なぜその運用なのかを押さえてください。困ったときに、自分で動けるようになるのがゴールです。ここで紹介するのは、実際の案件で効いている型だけです。 |
| 3 | Slack | まずスラックです。ポイントは、決定を流さないこと、そして通知は要る人にだけ、です。チャンネルは用途で使い分け、実務の細かいやり取りで全員にメンションしない。大事な決定は、スラックで流して消さずに、あとで出てくる決定事項シートに残します。そして、自分がメンションされたらスラックの通知が届くように設定しておく。確認漏れを防ぐためです。 |
| 4 | Backlog起票 | 次にバックログ、課題の起票です。コツは、きれいに整形してから登録するより、まず全部起票して、確認して、分からないものだけ後で直す、です。この方が全体が見えて早い。起票はテンプレートに沿って、背景、やりたいこと、確認事項を書く。そして粒度を意識して、カテゴリ、親、子、コメントに分けます。 |
| 5 | Backlogステータス | バックログのステータスは、実態を映すために使います。確認待ちで止まっている課題は、処理中のままにせず、内部確認中に変える。レビュー中、というステータスは、まだ作業が必要、という意味で全員が認識を合わせます。日本語が実態と少しズレても、運用で迷わないことを優先する。これが考え方です。 |
| 6 | 決定事項シート | 決定の置き場は、1枚だけにします。スラック、バックログ、定例、ミーティングで決まったことを、すべて1枚のシートに集約する。担当が日次で更新し、抜けに気づいた人は直接追記する。そして、仕様で迷ったら、まずここを見る。これをルールにします。 |
| 7 | 招待 | アカウント招待は、作業として確実に捌きます。バックログ、ギットハブ、Neonなど、連携に必要なアカウントは多い。招待が来たら、期限内に承認し、ログインできることまで確認する。依頼済みリストで未対応を見える化して、クライアントに同じ依頼を何度もさせない。これは技術以前の、信用の話です。 |
| 8 | ヒアリング議事録 | 現場へのヒアリングは、聞く計画を可視化します。誰が誰にいつ聞くかをスケジュール表で管理し、重複は同席で解消する。現場に同じことを何度も聞かない。協力してくれる気持ちは、有限の資源だからです。そして議事録は、全社共通の1箇所に集約します。 |
| 9 | GitHub PR | ギットハブとプルリクエストです。作業はブランチを切って、プルリクエスト、レビュー、そしてメインにマージ、という流れで進めます。コードだけでなく、画面設計書やAPI設計書もギットハブで管理し、同じ流れで更新する。確定した仕様を設計書に反映するところまでが、1セットです。 |
| 10 | 中間納品 | 中間納品の作法です。前工程が固まり切らなくても、期日には現時点の成果を出す。そのとき、未確定事項一覧を添えて、今後も更新する前提の中間納品にします。曖昧さは、隠すより可視化する方が、かえって信頼されます。 |
| 11 | 通知と会議 | 通知と会議は、要る人に、要る情報だけ、を意識します。実務の細かい会話では、不要なメンションを外す。内容が薄い、不参加が多い定例は、その回を中止してよい。惰性の会議を止めるのは、サボりではなく配慮です。 |
| 12 | 姿勢 | piponの基本姿勢です。依頼メモより、まず現場を見る。作ってから聞かない。資料より、動くもの、ワーキングプロダクトで会話する。そして確定を待たず、たたき台を出して議論を前に進める。この3つが、根っこにある考え方です。 |
| 13 | 困ったら | 困ったときに、まずどこを見るか。仕様で迷ったら、決定事項シート、次にバックログ。言葉が分からなければ、pipon用語辞典。誰に聞けばいいか分からなければ、ブリッジ役や先輩に投げる。それでも不明なら、確認事項として起票して回す。迷ったら止まらず、どこかに投げる、が基本です。 |
| 14 | やってはいけない | 逆に、これだけは避けてください。アカウント招待を放置して期限切れにすること。大事な決定を、口頭やダイレクトメッセージだけで済ませて残さないこと。用語を揃えないまま進めること。そして、要望を全部盛りで作ってしまうこと。どれも、あとで必ず効いてきます。 |
| 15 | まとめ | 型をまとめます。スラックは、決定を流さず通知は要る人に。バックログは、まず全部起票、ステータスは実態で。決定事項シートは、1枚に集約して日次更新。招待は、期限内承認とログイン確認まで。議事録とプルリクは、1箇所に集約し設計書も回す。そして姿勢は、見てから作る、動くもので会話する。これがpipon流・実務オペの型です。 |
