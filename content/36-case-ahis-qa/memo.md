# メモ：案件追体験 第5章「速いQA運用」動画版

日付: 2026-10-07
出典: 実案件Slackログ（#連携-jarmec-新ahis開発-マイページ2種、9〜10月）の再構成。顧客名・個人名は一般化。
対応: 案件シミュレーター第5章（case_ahis_ch5_scenario.json）の動画版。テーマは「品質を速く回す」。

6局面:
1. QAを整形してから出すか → 全部起票→PM確認→不明点だけ修正（全体が見えて早い）
2. ステータスが作業実態に合わない → 作業段階で定義、「レビュー中=要作業」の共通認識（言葉のズレは割り切り）
3. 論点が設計書なしだと分からない → 設計書を先にmain反映して前提を揃えてからQAを回す
4. タイトな期日 → 納品日から逆算して工程を日付で区切り、確定分だけで前に進める
5. 手隙メンバーに何を → 冗長性排除・関係性整理(A決まればC先)・回答案精査・実装デモ（流れを速くする整理）
6. 確定前の仕様で議論を止めるか → 既存画面の延長でAI仮デザイン→Slack共有、正式化は後（欠番OK）

型6か条: 整えてから渡すをやめる／ステータスは実態で設計／前提を先に揃える／逆算で日付区切り／手隙は整理に充てる／確定前でもたたき台で進める。
