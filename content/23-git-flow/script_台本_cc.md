# はじめてのGitとコマンド 第4回 Gitの基本の流れ — ナレーション台本

行数（7行）= スライド枚数（7枚）に一致させること。

| # | スライド | ナレーション |
|---|---|---|
| 1 | タイトル | はじめてのGitとコマンド、第4回です。今回は、Gitの基本の流れ。実際にどういう順番で使うのかを、覚えます。合言葉は、編集、アド、コミット、です。 |
| 2 | 全体像 | まず全体像です。Gitでは、三つの場所を、行き来するイメージを持つと分かりやすいです。一つ目、作業場。ふだんファイルを編集する場所です。二つ目、準備棚。保存したい変更を、選んで載せておく場所です。三つ目、保存庫。確定した履歴が、たまっていく場所です。作業場から、アドで準備棚へ、準備棚から、コミットで保存庫へ、と進んでいきます。 |
| 3 | はじめ方 | 始め方は、二通りあります。一つは、ギット、イニット。これは、今いるフォルダを、まっさらな状態から、Gitで管理し始めるコマンドです。もう一つは、ギット、クローン、そのあとにURL。これは、ネット上にあるプロジェクトを、丸ごと手元にコピーして始める方法です。どちらかを一度やれば、そのフォルダは、Gitの管理下になります。 |
| 4 | add | では手順です。手順の一つ目、ギット、アド。ファイルを編集したら、ギット、アド、ファイル名、と打って、準備棚に載せます。ギット、アド、ドット、と打てば、変更した全部を、まとめて載せられます。ここで大事なのは、まだ保存は確定していない、ということ。これは、保存する候補を選んだ、という段階です。 |
| 5 | commit | 手順の二つ目、ギット、コミット。ギット、コミット、ハイフンエム、そのあとにダブルクオーテーションで、やったことの説明、と打ちます。これで、準備棚の内容が、保存庫に記録されます。ハイフンエムのあとのメッセージには、何をしたかを、短く書きます。たとえば、ログイン画面を追加、のように。これで、一つの履歴、コミットが残り、あとで必ず、この時点に戻れます。メッセージは、未来の自分や仲間へのメモです。修正、とだけ書かず、中身を書きましょう。 |
| 6 | status log | 今どうなっているかを、確認するコマンドも大事です。ギット、ステータスは、今どのファイルが、変更されたか、アド済みかを、教えてくれます。これは本当によく使います。ギット、ログは、これまでのコミット、つまり保存の履歴を、一覧で見られます。迷ったら、ステータス。今の状態が、ひと目で分かります。 |
| 7 | まとめ | 第4回のまとめです。三つの場所、作業場から、アドで準備棚へ、コミットで保存庫へ。ギット、アドで選んで、ギット、コミット、ハイフンエム、説明、で保存する。そして困ったら、ギット、ステータス。次回は、こうして保存した履歴を、みんなで共有する仕組み、GitHubを学びます。 |
