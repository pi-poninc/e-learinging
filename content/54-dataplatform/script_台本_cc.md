# AIデータ基盤 Everything is an event ダイジェスト — 台本

行数（8行）= スライド枚数（8枚）。

| # | スライド | ナレーション |
|---|---|---|
| 1 | タイトル | AIプロダクトのデータ基盤、ダイジェスト。合言葉は、エブリシング・イズ・アン・イベント。障害監視も、分析も、顧客向けも、課金も、ひとつの基盤でまかなう考え方です。 |
| 2 | なぜ | 知りたいことは山ほど出てきます。障害、使われ方、顧客への価値、そして課金。これを別々に作ると数字がズレて破綻します。だから、あらゆる行動をひとつのイベントとして残し、意味づけは後から何通りでも作ります。 |
| 3 | 設計 | イベント設計が基盤の良し悪しを決めます。時刻、種類、テナント、そして詳細はプロパティに。名前は名詞・動詞で揃え、広く薄く、追記のみ。個人情報はマスキングと保持期間に注意します。 |
| 4 | 置き場所 | 置き場所は使い分けます。注文や契約、課金といった業務の正データはポストグレス。全行動ログのような大量のイベントは、列指向で集計が速いクリックハウスへ。無理にひとつにせず、まとめて投入し、イベントIDで重複を防ぎます。 |
| 5 | 集計 | 生のイベントは量が多く、毎回集計すると重い。そこでマテリアライズド・ビューで、あらかじめ集計を作り置きします。分や時間、テナント、種類ごとに集約し、ダッシュボードは小さな集計表を読むだけ。だから速い。 |
| 6 | 活用 | ひとつの基盤を四つの役で使い回します。エラー率やレイテンシの障害監視、どの機能が使われるかのプロダクト分析、テナント単位で切る顧客向けダッシュボード、そして課金KPI。みな同じ事実を見るので、ズレません。 |
| 7 | 課金 | AI時代の料金は、成果や使用量ベースに向かいます。課金の対象となる行動をイベントの種類で定義し、一件の数え方を顧客と合意する。そして請求と顧客ダッシュボードは、必ず同じ数字を見せます。 |
| 8 | まとめ | まず残す。正しさはポストグレス、量と速さはクリックハウス。マテリアライズド・ビューで集計し、ひとつの基盤で四役。課金KPIも監視や分析と同じイベントから作る。別計算にしないことが、信頼される料金の条件です。 |
