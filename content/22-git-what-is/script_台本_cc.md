# はじめてのGitとコマンド 第3回 Gitとは — ナレーション台本

| # | スライド | ナレーション |
|---|---|---|
| 1 | タイトル | はじめてのGitとコマンド、第3回です。いよいよ、Gitの登場です。名前は聞いたことがあっても、よく分からない、という方が多いと思います。今回は、Gitとは何か、を、保存の超進化版、というイメージでお話しします。 |
| 2 | Gitとは | Git、ギットとは、ファイルの変更を、履歴として記録する道具です。こういう仕組みのことを、バージョン管理、と呼びます。いつ、何を変えたかが、全部残ります。そして、好きな時点に、いつでも戻せます。これがGitの正体です。 |
| 3 | イメージ | もう少しイメージしやすく言いましょう。ふつうの保存、上書き保存は、保存すると、前の状態が消えてしまいますよね。でもGitは、保存するたびに、その時点の状態を、丸ごと記録します。だから、あとから全部見返せます。ゲームのセーブデータが、何百個でも、消えずに残っていく。そんなイメージです。 |
| 4 | なぜ必要1 | では、なぜそれが必要なのか。理由の一つ目と二つ目です。一つ目、間違えても、前の正しい状態に、すぐ戻せます。だから、安心して、いろいろ試せます。二つ目、いつ、誰が、どこを変えたかが、履歴で全部わかります。ファイル、アンダーバー、最終、アンダーバー、本当に最終、ブイツー、みたいな、あの悲劇から解放されるんです。 |
| 5 | なぜ必要3 | 三つ目の理由、これが大きいです。複数の人で、同じファイルを、安全に触れることです。何人かで、同じプロジェクトを、それぞれ編集して、あとで合体できます。しかも、誰かの変更で、別の人の作業が消えてしまう、という事故を防げます。だからこそ、開発の現場では、Gitがほぼ必ず使われています。作文でいえば、下書きの履歴が全部残って、共同で書けるノート、という感じですね。 |
| 6 | まとめ | 第3回のまとめです。Gitは、バージョン管理の道具で、変更を履歴として記録します。ふつうの保存と違って、過去の時点に、いつでも戻れます。そして、一つ、戻せる、二つ、誰が何を変えたか分かる、三つ、複数人で安全に作業できる。次回は、このGitを、実際にどう使うのか、基本の流れを覚えましょう。 |
