# メモ：案件追体験 第2章「複数社連携の開発マネジメント」動画版

日付: 2026-10-07
出典: 実案件Slackログ（#連携-jarmec-新ahis開発-all、8〜10月）の再構成。顧客名・個人名・社名は役割に一般化。
対応: 案件シミュレーター第2章（case_ahis_ch2_scenario.json）の動画版。

6局面:
1. 決定が散らばる → 決定事項シート1枚に集約・日次更新（迷ったらここ）
2. アカウント招待が行き渡らない → 招待を“作業”化（期限内承認＋ログイン確認＋依頼済みリスト）
3. 運用ルールをいつ決めるか → 粒度だけ先に、ルールは運用から後追いで育てる（「内部確認中」を必要時に追加）
4. 企画⇔開発の分断 → キーパーソンを開発チャンネルに常駐させ“確認の導線”を作る
5. 固まり切らない中の中間納品 → 「未確定事項一覧」を添えて更新前提で出す
6. 通知と会議に溺れる → 通知を要る人に絞る／惰性の定例は中止

型6か条: 決定の置き場を1つに／招待は作業として管理／ルールは後追い／境界に確認の導線／未確定を添えて納品／通知と会議を設計。
